# DV9AI Roadmap

This roadmap separates verified work from planned work. It is not a promise that every item is already implemented.

## Now

- Keep `main` green under CI: install, lint, test and build.
- Harden public-repository secret handling and contributor documentation.
- Preserve explicit owner gates and fail-closed runtime behavior.
- Improve observability without exposing credentials or personal data.
- Expand reproducible tests for Telegram gateway and deployment preflight.

## Next

- Document the broader DV9 orchestration architecture and module boundaries.
- Add machine-readable execution receipts for more runtime actions.
- Formalize state/recovery contracts for distributed workers.
- Add resource-aware scheduling and governor evidence to the public demonstrator track.
- Produce repeatable failure/recovery evidence for the TRL4 laboratory protocol.

## Later

- Broader agent orchestration interfaces.
- Edge-node registration and health evidence.
- Contributor-ready extension points for construction/engineering workflows.
- Public demo scenarios that can be reproduced from a clean environment.

## Acceptance rule

A roadmap item moves to "verified" only when there is evidence: code, tests, reproducible commands, logs/receipts or documented external validation as appropriate.
